# Grounding Record — Micron 64Mb SDRAM Refresh-Mode Handoff (1999), with Controller Transition Witness (2016)

## Purpose

This record grounds Case 21's bounded claim that a late-1990s Micron SDR SDRAM family exposed **two different loci for recurring refresh responsibility**:

- normal `AUTO REFRESH`, where the command is nonpersistent and must recur from outside the SDRAM while refresh-row addressing is generated internally;
- `SELF REFRESH`, where a CKE-controlled mode transition leaves the device to provide its own internal clocking and recurring refresh cycles until explicit exit.

The record does **not** claim that Micron invented self refresh, that the Micron document is itself the complete JEDEC standards history, or that every SDRAM implements the same internal circuit.

## Evidence status

**Grounding status: sufficient for `grounded` within the bounded manufacturer-product/interface scope.**

Why:

1. the central historical mechanism is stated directly in a period Micron manufacturer datasheet dated `Rev. 11/99`;
2. the document provides precise printed-page anchors and a functional block diagram rather than only later textbook reconstruction;
3. current Micron catalog evidence independently preserves the part-family identity/provenance;
4. a later Micron manufacturer PDF facsimile was visually inspected as a continuity/checking aid for the command semantics, but it is **not substituted for the 1999 date claim**;
5. Cases 09 and 10 already provide independent earlier primary evidence controlling false novelty claims about internal refresh counters and autonomous self-refresh scheduling;
6. `tmzncty/computing-archaeology` was searched for `SDRAM`, `SELF REFRESH`, `AUTO REFRESH`, and `CKE`; no dedicated overlapping retention case was found.
7. the 2016 Infineon XMC4700/XMC4800 reference manual supplies an independent manufacturer-primary controller/system witness for entry/exit request-versus-status and admission gating; a later official XMCLib API is used only as continuity evidence.

## Source 1 — Micron 64Mb x4/x8/x16 SDRAM, Rev. 11/99

**Source:** Micron Technology, Inc., _64Mb: x4, x8, x16 SDRAM_, document footer `64MSDRAM.p65 – Rev. 11/99`, ©1999 Micron Technology, Inc.

**Preserved copy used:** <https://pdf.elecfans.com/MICRON/MT48LC4M16A2.html>

The host is a later datasheet mirror/transcription; the artifact being cited is Micron's manufacturer document, whose footer, pagination, part numbers, and revision metadata are preserved in the transcription.

### Printed p. 1 — artifact identity and refresh headline

The first page identifies the family as:

- `MT48LC16M4A2` — 16 Meg × 4;
- `MT48LC8M8A2` — 8 Meg × 8;
- `MT48LC4M16A2` — 4 Meg × 16;
- 64Mb SDRAM;
- `Auto Refresh Modes`;
- `Self Refresh Modes: standard and low power`;
- `64ms, 4,096-cycle refresh`;
- footer `64MSDRAM.p65 – Rev. 11/99`.

This is the period anchor for the named product-family and date boundary.

### Printed pp. 4–6 — internal refresh-address/control path

The x4, x8, and x16 functional block diagrams show, among other blocks:

```text
CKE / CLK
CONTROL LOGIC
COMMAND DECODE
REFRESH COUNTER
ROW ADDRESS MUX
ROW ADDRESS LATCH & DECODER
MEMORY ARRAY
SENSE AMPLIFIERS
```

The diagrams therefore directly support an internal refresh-counter/address-path claim. They do not by themselves prove the detailed transistor-level implementation of that counter/controller.

### Printed p. 11 — command encoding and counter control

Truth Table 1 states that the same refresh command encoding is:

- `AUTO REFRESH` when `CKE` is HIGH;
- `SELF REFRESH` when `CKE` is LOW.

The notes state that the internal refresh counter controls row addressing and that external address/data inputs are irrelevant for the refresh operation (with CKE retaining its control significance for self refresh).

This directly separates **external command/mode selection** from **internal refresh-row enumeration**.

### Printed p. 13 — AUTO REFRESH

The manufacturer states that:

- `AUTO REFRESH` is used during normal operation;
- it is analogous to CBR refresh in conventional DRAMs;
- the command is **nonpersistent**, so it must be issued every time refresh is required;
- addressing is generated by the internal refresh controller;
- the 64Mb device requires 4,096 AUTO REFRESH cycles within 64 ms;
- distributed AUTO REFRESH commands at 15.625 µs intervals satisfy the requirement, while a burst alternative is also described.

The key retention result is not the numeric interval by itself. It is the partition:

```text
external recurring command
    !=
internal row-address generation
```

### Printed p. 13 — SELF REFRESH

The same page states that:

- SELF REFRESH can retain data even if the rest of the system is powered down;
- the SDRAM retains data without **external clocking** in this mode;
- entry is like AUTO REFRESH except CKE is LOW;
- after the command is registered, all other SDRAM inputs are `Don't Care` while CKE must remain LOW;
- the SDRAM supplies its own internal clocking and performs its own AUTO REFRESH cycles;
- the device may remain in the mode beyond the minimum `tRAS` interval.

This directly supports the shift from externally repeated refresh commands to internal recurring refresh work while the mode remains active.

### Printed p. 13 — exit and resumption

The exit sequence requires:

1. stable external `CLK` before CKE returns HIGH;
2. CKE HIGH;
3. NOP commands for `tXSR` (at least two clocks in this revision), because an internal refresh may still be in progress;
4. resumption of externally issued AUTO REFRESH commands at 15.625 µs or less after leaving self refresh.

Micron explicitly states that SELF REFRESH and AUTO REFRESH use the same row refresh counter.

This is the central evidence for a **reversible refresh-responsibility handoff** and for separating payload retention from immediate ordinary service resumption.

## Source 3 — later Micron facsimile check

A later Micron revision of the same 64Mb family was available as a page-renderable manufacturer PDF through a TI community attachment:

<https://e2e.ti.com/cfs-file/__key/CommunityServer-Discussions-Components-Files/109/7585.MT48LC4M16A2B4_2D00_6A_2D00_IT-SDRAM.pdf>

The PDF identifies itself as a later Micron revision (`Rev. Q 1/12 EN`). Printed AUTO REFRESH and SELF REFRESH operation pages were visually inspected in this research pass. They preserve the same important interface relations: nonpersistent externally issued AUTO REFRESH, internal refresh addressing, CKE-controlled self-refresh entry, internal clocking during self refresh, and an explicit self-refresh exit interval.

**Boundary:** this later facsimile is corroborative only. It cannot substitute for the `Rev. 11/99` evidence when making a statement specifically about the 1999 artifact.

## Source 4 — Infineon XMC4700/XMC4800 EBU reference manual, 2016

**Source:** Infineon Technologies AG, _XMC4700 / XMC4800 XMC4000 Family Reference Manual_, External Bus Unit (EBU) V1.6, manual V1.3, 2016-07.

**Official PDF:** <https://www.infineon.com/assets/row/public/documents/30/44/infineon-referencemanual-xmc4700-xmc4800-um-en.pdf>

### Printed p. 14-82 — system-side self-refresh sequencing

Section 14.12.18 states that SDRAM self refresh performs internal refresh sequences from an on-chip timer. For controller-managed entry, software writes `SELFREN`; the EBU precharges the banks and issues self refresh to all attached SDRAM devices. Read-only `SELFRENST` reflects the status of issuing/completing this command, and the manual explicitly makes successful completion the point after which power-down can be entered safely.

For exit, software writes `SELFREX`; the EBU asserts CKE for the SDRAM devices; read-only `SELFREXST` reflects completion, after which SDRAM accesses may proceed. The section then describes optional `ARFSH` work and `SELFREX_DLY`, a programmed NOP interval before later access.

This supports a controller-level distinction among **request**, **transition completion evidence**, **power-state admission**, and **ordinary access admission**. It does not directly measure cell-level retention margin.

### Printed pp. 14-120–14-122 — request/status register split

The SDRMREF register exposes separate fields for:

- writable `SELFREN` — issue Self Refresh Entry;
- read-only/status `SELFRENST` — entry command successfully issued;
- writable `SELFREX` — issue Self Refresh Exit / Power Up;
- read-only/status `SELFREXST` — exit command successfully issued;
- `SELFREX_DLY` — NOP cycles after exit before another command is permitted;
- `AUTOSELFR` — controller-managed automatic entry/exit around external-bus ownership.

The exact wording varies between the operational section and field descriptions (`completion` versus `successfully issued`). The repository therefore uses the conservative phrase **controller-observed transition/command-completion evidence** rather than treating the bit as a direct electrical proof of DRAM-cell state.

## Source 5 — later official Infineon XMCLib API continuity

## Prior-art control — Cases 09 and 10

Case 09 already grounds Texas Instruments 1980s CBR refresh behavior in which row enumeration is internal while refresh-request cadence remains externally controlled.

Case 10 already grounds Toshiba US4682306A, Japanese priority 20 August 1984, with on-chip self-refresh scheduling, oscillator, refresh-address counter, and leak-current monitoring. Toshiba's patent itself cites earlier Hitachi work on automatic refresh-frequency control.

Therefore the following claims are explicitly rejected:

- `Micron invented self refresh`;
- `SDRAM first internalized refresh-row addressing in 1999`;
- `the Micron 1999 datasheet establishes the invention priority of AUTO REFRESH or SELF REFRESH`.

The actual historical contribution of this case is a **named product/interface regime** in which the package boundary for recurring refresh work changes by mode.

## Failure / forgetting decomposition

The bounded evidence supports separating the following possible failure relations:

```text
payload retention deadline missed
    !=
external AUTO REFRESH command omitted/late
    !=
internal row-enumeration/control failure
    !=
SELF REFRESH mode-entry failure
    !=
loss of the powered self-refresh regime
    !=
self-refresh entry requested but not yet controller-qualified for power-down
    !=
exit requested but not yet controller-qualified for access
    !=
exit/recovery timing violation
    !=
ordinary-service unavailability while payload remains retained
```

No empirical failure-rate or field-reliability claim is made from the command specification alone.

## Cross-case contribution

Case 21 changes the comparison in ways Cases 03/09/10 alone did not establish at a named product interface:

- **refresh obligation ≠ recurring command-generation responsibility**;
- **internal refresh addressing ≠ autonomous recurrence**;
- **maintenance responsibility can be mode-transferred and reversible**;
- **retention availability ≠ ordinary service availability**;
- **self-refresh autonomy ≠ nonvolatility**;
- **mode-transition recovery timing can be constitutive infrastructure**;
- **self-refresh request ≠ controller-observed transition completion ≠ next-action admission**;
- **small control/status state can gate the retention treatment of a much larger payload without being payload itself**.

## Remaining work / explicit non-blockers

The case is grounded without closing these separate questions:

- exact JEDEC SDR SDRAM standard chronology and normative wording;
- invention priority for SDRAM refresh command encodings;
- exact internal oscillator/counter circuitry of this production part;
- temperature-compensated self refresh;
- DDR-generation refresh evolution;
- per-bank refresh;
- modern retention-aware refresh policy;
- empirical failure behavior of named Micron parts;
- controller/device composition under aborted entry/exit, controller reset, and real power sequencing;
- independent fault injection validating whether named systems actually honor entry/exit completion before power/access transitions.

Those are follow-on regimes, not hidden requirements for the bounded 1999 command/interface claim.
